# 系统架构说明

## 1. 架构目标

本项目以统一数据契约和统一算子契约隔离数据接入、算法研发、实验管理与平台部署。架构首先解决多人并行开发时的边界、一致性与可追溯性问题；具体技术框架、模型和服务协议将在需求和数据确认后选定。

核心原则如下：

- 分层组织，依赖指向稳定的公共契约。
- 数据处理与算法研发分离，算子不感知原始来源格式。
- 算法实现与平台部署分离，业务平台不依赖模型内部细节。
- 统一规范优先于算子局部便利。
- 数据、配置、代码、模型和结果均可版本化及追溯。

## 2. 逻辑数据流

```text
原始电网数据
      ↓
数据解析（parser）
      ↓
数据补全与场景生成（completion）
      ↓
统一图数据构建与校验（graph_builder + validator）
      ↓
统一电网图数据格式
      ↓
图学习算子（O1—O10）
      ↓
统一算子接口
      ↓
服务化封装与甲方平台集成
```

“场景生成”并非所有数据的必经改写步骤。真实数据无需补全或生成时，应保留原始观测；任何补全与生成结果必须携带方法、假设、质量和来源标识。校验不通过的数据不得进入正式算子流程。

## 3. 模块职责

### 3.1 数据层：`data/`

- `raw/nanjing/`：南京实际电网原始交付数据的逻辑落点。数据默认只读，并受授权、脱敏和版本策略管理。
- `raw/test/`：经批准的最小测试样本；不得从真实敏感数据中随意截取并提交。
- `processed/`：经过解析、标准化、补全、构图和校验的数据版本。
- `synthetic/`：具有明确生成依据、约束和适用范围的合成数据。

生产数据可实际存放在受控对象存储或数据平台中，本目录仅代表逻辑分层；仓库内不得提交未经授权的数据文件。

### 3.2 数据处理层：`data_pipeline/`

- `parser/`：读取来源格式，完成字段识别、编码转换、单位标准化和来源元数据提取；不承担模型任务。
- `completion/`：在明确策略下处理缺失信息或生成受约束场景；必须保留原始值、缺失掩码、方法和置信信息。
- `graph_builder/`：把已解析的数据映射为 `dataset_spec.md` 定义的节点、边、时序、标签及关联索引。
- `validator/`：检查结构、类型、单位、引用完整性、时间对齐、电气合理性和规范版本。

数据处理流程只产出统一数据包，不为某个算子定制私有格式。算子所需的批处理或张量布局属于算子适配过程，不改变标准数据包语义。

### 3.3 算子研发层：`operators/`

- `base/`：未来放置经评审的最小统一算子契约和共享生命周期约定，不放具体模型。
- `O1_*` 至 `O10_*`：各算子的独立研发空间，包含其业务说明、配置、实现和专属测试（在进入实现阶段后逐步添加）。

算子仅消费通过校验的统一数据包，并按 `operator_spec.md` 提供一致的元数据、训练、评估和推理语义。算子不得直接读取其他算子内部文件，也不得把框架内部对象暴露给部署层。

### 3.4 公共组件层：`common/`

- `graph/`：统一图数据对象、图变换契约和通用图操作。
- `metrics/`：经过定义和验证的跨算子评价指标。
- `configs/`：共享配置模式、默认约定及配置校验。
- `utils/`：少量无法归入上述领域、且确有多个使用方的通用能力。

公共组件必须职责单一、稳定且不依赖具体算子。仅有单一使用方的逻辑先保留在使用方内部，避免过早抽象。

### 3.5 实验管理层：`experiments/`

负责实验配置、运行清单、结果索引和报告组织。实验层编排数据版本与算子版本，但不复制算子核心代码，也不把大型模型产物直接纳入 Git。统一要求见 `experiment_spec.md`。

### 3.6 部署层：`deployment/`

负责算子注册、模型封装、在线或批量推理适配、版本发布、健康检查、监控与甲方平台协议转换。部署层通过统一算子接口调用算子，不修改算法内部数据语义。

## 4. 依赖与契约边界

推荐依赖方向为：

```text
甲方平台 → deployment → operators → common
                         ↘
experiments ─────────────→ operators
data/raw → data_pipeline → 统一数据包 → operators
```

约束：

- `common` 不依赖 `operators`、`experiments` 或 `deployment`。
- `operators/Ox` 不依赖其他具体算子。
- `data_pipeline` 不依赖具体算子，也不包含任务模型。
- `deployment` 不直接解析原始数据或访问模型内部结构。
- 共享契约的破坏性变更必须升级版本并给出迁移策略。

## 5. 数据与版本追踪

一次可复现运行至少关联以下标识：数据规范版本、数据集版本、处理流程版本、算子版本、配置摘要、代码提交、运行环境和结果位置。原始数据、加工数据、合成数据不得仅凭目录名区分来源；每个正式数据包都应带清单和血缘信息。

## 6. 平台集成边界

后续集成采用“平台请求/数据引用—统一推理请求—统一结果—状态与错误信息”的边界。具体传输协议、鉴权、同步或异步模式在甲方接口确定后设计。当前阶段只固定领域语义，不提前绑定 Web 框架、消息队列、模型服务框架或云平台。

## 7. 非当前范围

当前不实现数据接入、补全算法、场景生成算法、GNN 模型、训练评估程序、推理服务或平台接口；也不选定深度学习、实验跟踪和部署框架。
